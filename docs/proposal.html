Attaché
Design proposal · v0.7 · 20 October 2026
A Python take on nanoclaw

A personal assistant you install with one command

Attaché runs on your own machine. You talk to it in a terminal, on a local web page and in your chat apps, including group chats. It keeps its know-how in a folder of skills, and it rewrites those skills as your habits change. The core stays small enough to read in an afternoon. Everything else is a skill.

$ uvx attache                 # try it without installing
$ uv tool install attache     # keep it
$ attache init && attache run
  • Python 3.11+
  • about 1,500 lines of code
  • 6 direct dependencies
  • Claude API, Claude Code, OpenAI, any compatible endpoint
  • Slack and Signal first, more channels as skills
  • Outlook, Gmail and Titan mail

The name is attache, after the assistant on an ambassador's staff and the case an executive carries. It was unclaimed on PyPI on 19 October 2026, so register it before the first release.

Changes in v0.7
  • Phase 2 is built, in pull request #34. It adds Slack and Signal as skills that run a sidecar program over JSON lines, approvals, rate limits for group chats, and the render skill. Three review rounds, for correctness, security and simplicity, checked it, and it has 412 tests.
  • The core cap is now 1,900 lines of code, raised for the channels, approvals and their hardening. The core fills it exactly, so phase 3's core work needs cuts or a budget decision of its own (D9, §10).
  • When a member asks for something only you can do, you see their words verbatim, at most 300 characters, and the work runs as your turn only if you approve. A typed answer counts only when exactly one question is open (§8).
  • Sidecars run in their own process group, without the model API keys, and may only hand over files from their own inbox. The render browser can reach nothing but Attaché's own pages (§3, §7).
  • v0.6: phase 1 built (pull request #28, version 0.0.1), the OpenAfterHours theme, Claude Code reaching Attaché's tools over MCP, and one conversation shared by the terminal and the web page.

§1

The proposal in ten decisions

  1. D1

    One small package

    Python 3.11+, installed with uv, running as one asyncio process. All state lives in ~/.attache, or wherever ATTACHE_HOME points. The same package runs in Docker later.

  2. D2

    Every optional capability is a skill

    One folder of Agent Skills directories holds four kinds of skill: knowledge, scripts, channels and artifact templates. The core never learns about Gmail or Slack.

  3. D3

    Skills are living documents

    The agent edits a skill when you change how you work. ~/.attache is a git repo, so every edit is a commit you can read and undo. Only your own messages can change a skill.

  4. D4

    Model backends are config rows

    Four small adapters: anthropic, openai-chat, openai-responses and claude-cli. Any endpoint that speaks one of those protocols is one block of TOML. Your own chats use your Claude login, and group chats use an API key. No LiteLLM and no agent framework.

  5. D5

    Channels run as sidecar processes

    Each channel skill ships a channel.py that uv runs with its own dependencies. It talks to the core in JSON lines over stdin and stdout. Slack and Signal come first. Each sidecar shows approval requests its own way: buttons in Slack, a reaction prompt in Signal.

  6. D6

    Artifacts are local pages over real data

    The agent writes HTML. The built-in server adds a small attache bridge to the SQLite store, with live updates. People in chat apps get a PNG snapshot and a signed link.

  7. D7

    Group chats follow a fixed policy

    Access, then trigger, then role. Each role has its own toolset, and a guest's turn never has private data and outbound sending at the same time.

  8. D8

    Three surfaces, each with one job

    The CLI sets up and operates. One local web page holds chat and artifacts. Chat apps cover the phone and the group.

  9. D9

    Size is a test

    CI fails if the core passes 1,900 lines of code. Blank lines, comments and docstrings don't count, so the budget never rewards dense code. New features arrive as skills, and the contribution guide says so.

  10. D10

    One mail skill for every account

    Outlook through Outlook classic's COM interface or Microsoft Graph with OAuth, your choice per account. Gmail and Titan over IMAP. All behind the same commands. It reads and files on its own, saves replies as drafts, and sends only after your yes.

Keep from nanoclaw

  • “Skills over features” as a written rule.
  • One memory file per chat, plus a global one.
  • Engage modes: mention, mention-sticky and pattern.
  • One owner chat with admin rights. Other chats are restricted.
  • Scheduled tasks run as ordinary turns in a chat.

Change for a pip package

  • A uv-installed tool has no fork to rewrite. nanoclaw's /add-slack edits source code. Here the slack skill adds Slack at runtime by shipping its own sidecar.
  • Not tied to one vendor. Four adapters from day one.
  • A web page for chat and artifacts. nanoclaw ruled one out (“we're not adding a web UI at this stage”, PR #212). Interactive artifacts need a page to live in.
  • No container requirement, so uvx attache works on a laptop with nothing else installed.
  • A size budget enforced by a test. nanoclaw grew about 17 times past its launch size, and nanobot about 50 times.
§3

Architecture

One process. Channels feed a router, the router builds a turn, a backend runs it, and tools act on the world. All state lives in one folder and one SQLite file.

One message, start to finish

  1. Jo writes “@Attaché can you send the packing list as a PDF?” in the family Signal group. The Signal sidecar, a thin wrapper around signal-cli's JSON-RPC mode, turns it into one JSON line on its stdout.
  2. The router checks that the chat is allowed, sees the mention and looks Jo up as a member. Members can use this chat's files, send to this chat only, use shared collections and make artifacts.
  3. It builds the turn: the persona, this chat's memory file, the full text of the skills members may use, the last 30 messages with other people's words fenced and labelled as data, and Jo's identity taken from the config. Your own USER.md stays out of anyone else's turn.
  4. The backend runs the loop. The model follows the pdf skill, runs its script through the script tool (which uses uv run), and calls send with the file.
  5. The core writes a send line to the sidecar's stdin, and the bot posts the PDF to the group with a caption.

  • Only turns from the owner can write under skills/. When a member asks for a change, such as “always send the shopping list as a checklist”, the assistant drafts the edit and sends it to your DM for a yes or no.
  • After any turn that touched skills/ or memory/, the core commits with the request as the message. attache skills undo mailbox reverts the last change.

  • New abilities arrive the same way. Asked to “add Signal”, the agent drafts skills/signal/ with a channel.py that talks to signal-cli. You review the commit, and it starts on the next restart.

Outlook uses either Outlook classic on this PC through its COM interface, or Microsoft Graph with an OAuth sign-in; you pick per account. Gmail and Titan use IMAP with SMTP. Your filing rules live in the mailbox knowledge skill, so they don't change with the backend.

How sending works

  1. The agent saves the reply in that account's Drafts and shows it to you in your Slack DM.
  2. Your yes runs send-draft with a confirmation token, a hash of the recipients, subject and body you saw. If the draft changed in between, the send is refused.
  3. Outlook sends it itself, through COM or Graph. Gmail and Titan send through SMTP, with a fixed Message-ID so a retry can't send twice. Titan doesn't file sent mail on its own, so the skill copies it to Sent.
  4. Every action, read or write, is appended to ~/.attache/logs/mail.jsonl.

An inbox holds private data, untrusted content and a way to send, all in one place. So the assistant never follows instructions found inside an email, never adds recipients taken from email text, and runs this skill only on your own turns.

Limits to plan for

  • Only classic Outlook has COM; the new Outlook app has none. If you switch, mail doctor says so; set the account to Graph and it carries on. Microsoft supports existing classic installs until at least 2029.
  • Attaché has to run in your own logged-in session without elevated rights. Windows refuses the connection when one side is elevated and the other isn't, and Microsoft doesn't support Office automation from background services. attache service install sets up the scheduled task this way.
  • Outlook shows security prompts when antivirus isn't reported healthy or a policy forces them. On a home PC with Defender up to date it is normally silent.
  • Outlook updates occasionally break COM. An April 2026 Current Channel build did until Microsoft fixed it in May, which is one reason doctor exists.
  • A Graph sign-in lapses after 90 days without use or when you change your Microsoft password, and some work tenants block sign-in to unverified apps. doctor names the cause and asks you to run login again.
  • Gmail revokes app passwords whenever you change your Google password. doctor spots the failed sign-in and asks you for a new one.
  • Titan caps mail to outside addresses by plan, from 50 an hour on Starter. Approved sends are few, but the skill still counts recipients and limits each run.
Off this PC

Gmail, Titan and Outlook through Graph work wherever Attaché runs. Only the COM route ties the Outlook account to this PC. EWS isn't an option: Microsoft starts blocking it in Exchange Online on 1 October 2026 and removes it on 1 April 2027.

Budget, estimated: about 1,100 lines in four files. Shared commands about 150, COM about 300, IMAP about 250 with IMAPClient, Graph about 400 with msal. Capped at 1,200. It is the biggest skill, and it is still outside the core. Early open-source Outlook MCP servers such as outlook-classic-mcp and Robvred/outlook-mcp are useful for patterns: one Outlook thread, draft-only defaults and an audit log.

agent.py, the whole shared loop
class Backend(Protocol):
    async def run(self, turn: Turn) -> Reply: ...

async def tool_loop(complete, turn, steps=20):
    msgs = turn.history + [user(turn.text)]
    for _ in range(steps):
        out = await complete(turn.system, msgs,
                             turn.tools)
        msgs.append(out.message)
        if not out.calls:
            return Reply(out.text)
        msgs.append(await run_tools(out.calls, turn))
    return Reply("I stopped after 20 steps.")

Each API adapter only implements complete(): one request, translated to and from a shared message format. run_tools checks every call against the sender's role first.

  • Official SDKs only. anthropic and openai together resolve to 17 packages. LiteLLM resolves to 59, shipped 241 releases in 2026, and had two compromised PyPI releases (1.82.7 and 1.82.8) on 24 March 2026. nanobot replaced it with the two SDKs that day.
  • Why two OpenAI adapters. From GPT-5.4 on, Chat Completions only allows tool calls when reasoning_effort is none, so OpenAI's own reasoning models need Responses. Local and hosted compatible servers mostly speak Chat Completions.
  • How claude-cli works. It runs claude -p --output-format stream-json --verbose --resume <session> in a folder outside your home, keeps one Claude session per chat, and points --mcp-config at an MCP endpoint on the local web server, which serves only Attaché's own tools (Claude Code brings its own file and shell tools). When a session starts fresh it gets the earlier conversation as a transcript. It only answers your own chats, never a group. The claude-agent-sdk package does the same thing in-process, but it bundles the CLI (104 to 117 MB per platform wheel), so it stays an optional extra.
  • Subscriptions. Anthropic's terms allow a Pro or Max login for your own individual use. Anything that serves other people should use an API key. Your choice follows that: claude-cli on your login for your own chats, claude-api with a key for group chats. A chat can still name its own endpoint. If ANTHROPIC_API_KEY is set, claude -p uses it instead of your login.

An artifact is an HTML file the agent writes into artifacts/. The local server serves it with a small bridge script, so a to-do board edits the real to-do collection. An open page updates when the agent or someone else changes the data. Try the example below; the log on the right shows the calls the page would make.

    How it reaches people

    1. The agent calls artifact(name="trip-checklist", html=…); the page declares <meta name="attache-collections" content="trip">.
    2. In the web app the page opens in a sandboxed frame. It can't reach the internet, other pages or any data it didn't declare.
    3. In a chat app the reply is a PNG snapshot plus a signed link that expires. The signature is an HMAC from the standard library. Links are not single-use, because link-preview crawlers open them first.
    4. On a laptop, links go out through Tailscale Funnel when you turn sharing on. In the cloud they use the public URL. Cloudflare quick tunnels also work but drop live updates, since they don't pass SSE.

    §8

    Group chats and people

    In a group anyone can talk to Attaché, so the router settles three questions in a fixed order before a model sees anything.

    1. 1 · ACCESS

      Is this chat allowed?

      Chats and people are listed in attache.toml, keyed by platform IDs, never display names. Unknown chats are ignored.

    2. 2 · TRIGGER

      Was Attaché addressed?

      A mention, a reply to the bot, or the chat's pattern. Other messages are stored as context and never answered.

    3. 3 · ROLE

      Who is asking?

      Owner, member or guest. The role decides which tools the turn gets.

    Safeguards

    • A guest's turn never gets private data and outbound sending together. That combination, plus untrusted input, is what Simon Willison calls the “lethal trifecta”.
    • Unmentioned messages enter the prompt fenced and labelled as transcript, never as instructions. Forged headers in message text are stripped.
    • Each sender and each chat gets an hourly rate limit, and non-owner turns a daily cap, set under [limits]. A chat that hits one hears so once.
    • The bot ignores its own messages and other bots.
    • Sending to a different chat needs your confirmation.
    • In Slack the bot only sees channels it has been invited to. In Signal it only sees groups it has been added to, and it knows people by their Signal account ID, because phone numbers are hidden by default.

    Shared lists

    Members of a chat can tick off items on any list shared with that chat. Both ways of ticking update the same record, so every open copy of the list changes at once.

    • In the chat: “@Attaché tick off passports”. The tick is credited to the sender, because the router knows who they are.
    • On the list's page, from the link the bot posted. That link can change only that list, expires, and can be revoked. Ticks made there are logged as “via the Family link”, because a shared link can't tell people apart.
    • Members can add items too. Only you can delete a list, change who it is shared with or revoke its link. If you'd rather members only tick, that is one setting.

    The Home view is itself an artifact built from artifact-kit: today's to-dos, reminders and pinned pages. Ask for a different layout and the agent edits it. The web UI code stays a chat box and an artifact frame.

    attache service install keeps it running after login, using launchd on macOS, a systemd user unit on Linux and Task Scheduler on Windows.     §10

    Code budget

    Phase 1 came in at 1,576 lines of code in src/attache, against a cap of 1,600 that CI enforces. Phase 2 added the sidecar runner, approvals, rate limits and the hardening its reviews asked for. The simplicity review cut 54 lines first, and the owner then raised the cap to 1,900, with a target of about 1,850. The core ended phase 2 at exactly 1,900, so phase 3's core work (sharing, attache.ask from pages, the service) needs cuts or a budget decision of its own; the mail, file and knowledge work is all skills. Blank lines, comments and docstrings don't count, so the budget never pushes code to be denser than it should be. Bundled skills, static files and tests don't count either, but each bundled skill has its own cap: 300 lines by default, 1,200 for mail, which has three backends.

    Risks and decisions

    RiskMitigation
    The core growsThe budget test D9, features as skills D2, and a CONTRIBUTING rule copied from nanoclaw.
    A message or email tries to steer the assistantIncoming content is marked untrusted and never treated as instructions. Sending email, forwarding and messaging other chats need your yes D7 D10.
    Microsoft moves you to new OutlookClassic installs are supported until at least 2029. mail doctor detects the switch, and one line in accounts.toml moves the account to Graph.
    A Graph sign-in expires or is blockeddoctor separates expiry, consent and policy problems and asks you to sign in again. On this PC, COM stays available as a fallback.
    Mail passwords leakStored in Windows Credential Manager through keyring, never in attache.toml or git. App passwords can be revoked on their own without touching your main password.
    signal-cli stops working after a Signal changeattache doctor checks its version, and the signal skill updates it. Releases come about monthly, and versions older than three months may fail.
    Signal flags the bot's numberA dedicated number, low volume, and replies only to people who write to it, plus your own reminders.
    Slack free plan limitsAttaché keeps its own message history in SQLite, so 90 days of visible Slack history doesn't limit its memory.
    Prompt injection in groupsToolsets by role, the trifecta rule, fenced context D7.
    Shell access on the hostrun and the file tools are owner-only and confined to ~/.attache, with .secret, the database and git blocked. claude-cli uses Claude Code's own permissions on your login, runs outside your home, and only answers your own chats. Docker for run comes later as an option.
    Subscription termsGroup chats default to an API-key endpoint.
    Weak tool calling on local modelsTolerant argument parsing, a list of tested models, and a model choice per chat.
    CLI output formats changeParse only assistant text and the final result, and test against recorded fixtures. Pin versions.
    Windows differencesCopies instead of symlinks, Task Scheduler for the service, and CI on Windows from the start.

    Decided on 19 October

    • Name: attache.
    • Chat apps: Slack and Signal, both in phase 2, with Signal on your separate number. Telegram and WhatsApp are out of scope.
    • Models: your Claude login (claude-cli) for your own chats, an API key (claude-api) for group chats.
    • Email: Outlook through COM or Microsoft Graph with OAuth, chosen per account; Gmail and Titan over IMAP; all through the mail skill.
    • Shared lists: members of a chat can tick off items on lists shared with it.

    Deferred

    • Cloud target. Nothing before phase 4 depends on it. Keeping everything in one folder under git, with Docker as the packaging, leaves Fly.io, Railway, a VPS and a home server all open.

    • Phase 2, Signal: Java 25 on this PC, then registering your separate number with a captcha and an SMS or voice code. Registering signs out any Signal app already using that number, so keep it for Attaché alone.
    • Phase 3, Gmail: 2-Step Verification on, then an app password.
    • Phase 3, Outlook through Graph (optional): a free Azure account for an Entra tenant, an app registration (desktop app, redirect http://localhost, delegated mail, calendar and tasks permissions), then mail.py login outlook.
    • Phase 3, Titan: “Enable Titan on Other Apps” in webmail, and an Application Password if 2FA is on.
